> **学习版批注（以同目录当前 TypeScript 实现为准）**
>
> 阅读时先跟踪两条时间线：update推进本地计数器；addServerFrame接入网络数据。两者不是同一个定时队列。
> delay参与原始帧→缓存帧的映射和服务器目标对齐，普通onServerFrame不会统一等待delay帧后才调用。
> 追帧2/6是每次update额外补跑额度，不限制前面按dt推进的while；卡顿后实际执行可以集中发生。
> 硬对齐判断用绝对差>20，既可能向前也可能向后；只改计数器，不补执行中间所有玩法。首次对齐要目标帧>0。
> replay批次仅延后业务派发，缓存、校正、硬对齐仍可能发生；无onServerFrameBatch时当前只派发最后一帧。
> 校正匹配是客户端操作__rid与seqId同时相等；位置阈值内仅标NORMAL，朝向差异不会独立触发校正。
> 注释中的服务器与本地差delay是框架的目标约定，不是网络天然保证始终成立的事实。以下为原有流程文档。

# 帧同步通用框架 — 数据流与时序

## 一、正常帧同步数据流

### 1.1 服务器帧处理流程

```
服务器 ──(TCP)──→ MsgMgr 消息分发
                    │
                    ▼
            协议层 (Protocol)
            revServerFrameMsg()
            ├─ 解析 Thrift/Protobuf 消息
            ├─ 坐标 ÷10000 还原
            └─ onFrameReceived(frameData)
                    │
                    ▼
            驱动层 (Driver)
            addServerFrame(rawMsg, frameIndex, roomId)
            ├─ 缺帧检测
            │   ├─ frameIndex < expectedNext → 忽略旧帧
            │   ├─ frameIndex > expectedNext → sendReconnect() 并 return
            │   └─ frameIndex == expectedNext → 正常处理
            ├─ convertRawMsgToFrameData(rawMsg)
            └─ clientSyncManager.addServerFrame(frameData)
                    │
                    ▼
            核心控制器 (SyncManager)
            addServerFrame(frameData)
            ├─ 1. alignClientFrameToServer() — 首次/强制对齐
            ├─ 2. processServerFrameData()
            │   ├─ frameBuffer.addServerFrame() — 存入缓冲区
            │   ├─ corrector.correctFrame()    — 服务器矫正
            │   └─ dataHandler.onServerFrame() — 派发到逻辑层
            ├─ 3. serverFrame = max(serverFrame, index)
            ├─ 4. syncClientFrameWithServer() — 追帧欠账计算
            └─ 5. updateNetworkStats()
                    │
                    ▼
            逻辑层 (GameLogic)
            onServerFrame(frameData)
            ├─ 更新游戏状态（玩家位置、道具、倒计时等）
            └─ 通知渲染层刷新表现
```

### 1.2 客户端帧处理流程

```
玩家操作（摇杆/技能/拾取）
         │
         ▼
    驱动层 (Driver)
    ├─ protocol.sendFrame(params) ──→ 服务器
    └─ addClientFrame(frameIndex, frameInfo)
         │
         ▼
    核心控制器 (SyncManager)
    addClientFrame(frameIndex, frameInfo)
    ├─ alignedIndex = frameIndex + serverFrameDelay
    ├─ frameBuffer.addClientFrame(alignedIndex, frameInfo)
    └─ [如果启用预测] predictor.predictNextFrame()
         └─ frameBuffer.addClientFrame(alignedIndex+1, predictFrame)
```

### 1.3 帧驱动流程（主循环 update）

```
Scene.update(dt)
    │
    ├─ driver.updateLogicFrame(dt)
    │   │
    │   ▼
    │   SyncManager.updateLogicFrame(dt)
    │   ├─ logicFrameTime += dt (微秒精度)
    │   ├─ while (logicFrameTime >= interval)
    │   │   └─ advanceLogicFrameOnce()
    │   │       ├─ currentLogicFrame++
    │   │       ├─ frameBuffer.cleanup(过期帧)
    │   │       ├─ checkLostFrames() → emit FRAME_LOST
    │   │       ├─ getClientFrame() → dataHandler.onClientFrame()
    │   │       └─ emit FRAME_UPDATE {type: "logic"}
    │   │
    │   └─ 追帧策略（不在批处理期间执行）
    │       ├─ diff ≤ 10：软补跑（每次最多 2 帧）
    │       └─ diff > 10：按欠账补跑（每次最多 6 帧）
    │
    └─ driver.updateRenderFrame(dt)
        │
        ▼
        SyncManager.updateRenderFrame(dt)
        ├─ renderFrameTime += dt (微秒精度)
        └─ while (renderFrameTime >= interval)
            ├─ currentRenderFrame++
            └─ emit FRAME_UPDATE {type: "render", targetLogicFrame}
```

```
                    expectedLogicFrame = serverFrame - serverFrameDelay
                           │
              diff = expectedLogicFrame - currentLogicFrame

         ┌─────────────────┼─────────────────┐
         │                 │                  │

                     (updateLogic中)     ≤6帧/tick         (alignClient
                                        (updateLogic中)    ToServer中)
```

## 三、断线重连时序

```
时间线
  │
  │  正常帧: #1 → #2 → ... → #499 (lastContiguous=499)
  │
  │  ──── 网络断开 ────
  │
  │  收到 #600（缺口：500~599）
  │  ├─ expectedNext = 500, incoming = 600 → 缺口
  │  ├─ pendingReconnect = 500
  │  └─ protocol.sendReconnect(roomId, 500)
  │
  │  ──── 等待重连响应 ────
  │  （期间收到的 #601, #602... 因 > expectedNext 被忽略）
  │
  │  收到重连响应（包含 #500 ~ #610 的历史帧）
  │  │
  │  ▼
  │  driver.reconnectGame(roomId, historyFrames)
  │  ├─ beginServerFrameReplayBatch()
  │  ├─ for each frame: syncManager.addServerFrame(frame)
  │  │   ├─ frameBuffer.addServerFrame()
  │  │   ├─ corrector.correctFrame()
  │  │   └─ pendingServerFrameDataMap.set(frameIndex, frame)
  │  ├─ lastContiguous = 610
  │  ├─ pendingReconnect = null
  │  └─ endServerFrameBatch(flush=true)
  │      └─ dataHandler.onServerFrameBatch(sortedFrames)
  │          └─ 逻辑层按序消费追帧数据
  │
  │  ──── 恢复正常 ────
  │
  │  收到 #611 → 正常处理（expectedNext=611）
```

## 四、帧号对齐机制

框架中存在两套帧号：

| 名称 | 说明 | 示例 |
|------|------|------|
| 原始帧号 | 游戏逻辑层使用的帧号 | 70 |
| 对齐帧号 | 加上 serverFrameDelay 后的帧号，用于与服务器帧对齐 | 70 + 5 = 75 |

### 对齐规则

```
客户端帧存储:  alignedIndex = originalIndex + serverFrameDelay
客户端帧读取:  alignedIndex = originalIndex + serverFrameDelay
客户端帧返回:  frameData.frameIndex = originalIndex  (给服务器用原始帧号)
服务器帧:     直接用 frameData.frameIndex（已经是带延迟的帧号）
```

### 意义

服务器帧号天然比客户端逻辑帧号大 `serverFrameDelay` 帧。客户端帧存储时 +delay，使两者在缓冲区中以相同的帧号对齐，方便矫正器逐帧对比。

## 五、批处理模式对比

### latest 模式（beginServerFrameBatch）

适用场景：进房时快速同步到最新状态。

```
batch 期间:  收到 #100, #101, #102, #103
              └─ 只保留 #103（最新帧）
endBatch:    dataHandler.onServerFrame(#103)
```

### replay 模式（beginServerFrameReplayBatch）

适用场景：重连追帧，需要按序回放历史。

```
batch 期间:  收到 #500, #501, ..., #599, #600
              └─ 全部收集到 Map<frameIndex, FrameData>
endBatch:    按 frameIndex 排序
             ├─ dataHandler.onServerFrameBatch([#500, ..., #600])  (优先)
             └─ 回退: dataHandler.onServerFrame(#600)              (未实现 batch 时)
```

## 六、帧矫正流程

```
correctFrame(frameIndex, serverFrame)
    │
    ├─ 获取 clientFrame = frameBuffer.getClientFrame(frameIndex)
    │
    ├─ clientFrame 不存在
    │   └─ createFrameFromServer() — 直接用服务器数据创建，标记 NORMAL
    │
    └─ clientFrame 存在
        └─ mergeServerFrame()
            ├─ 找到对应玩家 (getPlayerKey)
            │   ├─ 计算位置偏差 distance
            │   │   ├─ distance ≤ threshold → 标记 NORMAL（不矫正）
            │   │   └─ distance > threshold → applyCorrection()
            │   │       ├─ 标记 LOCAL_CORRECTION
            │   │       └─ 覆写 x, y, direction（经 normalizeDirection 处理）
            │   │
            └─ 未找到对应玩家 → 追加新的 info 条目
```

## 七、关键常量

| 常量 | 值 | 说明 |
|------|-----|------|
| MAX_SOFT_SYNC_DIFF | 10 | 小落后阈值（≤10 帧走软补跑） |
| MAX_CATCH_UP_LOGIC_FRAMES_PER_UPDATE | 2 | 软补跑每 tick 最多追帧数 |
| MAX_FAST_CATCH_UP_LOGIC_FRAMES_PER_UPDATE | 6 | 欠账追赶每 tick 最多追帧数 |
| 强制对齐阈值 | 20 | 帧差 > 20 时硬同步跳帧 |
| TIME_SCALE | 1000000 | 微秒精度（避免浮点数累积误差） |
| 矫正阈值 | 0.1 | 位置偏差超过此值才矫正 |
