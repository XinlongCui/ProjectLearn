# 帧同步通用框架 — 接入指南

## 概述

本文档以分步骤方式指导新玩法接入帧同步框架。以「color_game（抢礼物小游戏）」为真实案例加以说明。

> 参考代码：`example/` 目录下的接入示例（以「抢宝小游戏」为场景）。

---

## 第一步：定义玩法数据类型

继承框架基础数据模型，添加玩法专属字段。

### 需要扩展的基类

| 基类 | 说明 | 扩展方式 |
|------|------|----------|
| `MngBasePlayerInfo` | 玩家简要信息 | interface 继承，加 `campId` / `skinId` 等 |
| `MngBaseFrameInfo` | 单次帧操作信息 | class 继承，加 `itemId` / `skillId` / `actionType` 等 |
| `MngBaseFrameInfos<TInfo>` | 一帧内单个玩家全部数据 | class 继承，加 `campId` / `itemIds` 等 |
| `MngBaseFrameData<TFrameInfos>` | 一帧内所有玩家数据 | class 继承，加 `mapGift` / `remainTime` 等 |
| `MngFrameSendParams` | 发送帧数据参数 | interface 继承，加 `giftId` / `bagIndex` 等 |

### 示例（color_game）

```typescript
// client_frame_data.ts

export interface FrameInfo extends MngBaseFrameInfo {
    itemId?: number;    // 携带的箱子ID
    bagId?: number;     // 仓库格子ID
}

export interface FrameInfos extends MngBaseFrameInfos<FrameInfo> {
    campId?: number;    // 阵营ID
    itemIds?: number[]; // 背包内道具列表
}

export interface FrameData extends MngBaseFrameData<FrameInfos> {
    mapGift?: number[]; // 场景道具刷新点状态（9个出生点）
}
```

## 第二步：实现协议层

继承 `MngBaseFrameSyncProtocol`，实现 4 个核心方法。

### 必须实现

| 方法 | 说明 |
|------|------|
| `registerMsg()` | 用 `MsgMgr.regMsgHandler` 注册服务器帧消息和重连消息 |
| `unregisterMsg()` | 用 `MsgMgr.unregMsgHandler` 注销 |
| `sendFrame(params)` | 构造 `sg.CgXxx` 消息并通过 `MsgMgr.sendMsg` 发送 |
| `sendReconnect(roomId, frameIndex)` | 构造重连请求消息并发送 |

### 关键细节

1. **坐标精度**：发送时乘以 10000 取整，接收时除以 10000 还原
2. **消息回调中**：解析消息后调用 `this.onFrameReceived?.(frameData)` 递交驱动层
3. **重连回调中**：调用 `this.onReconnectReceived?.(roomId, roomInfo)` 递交驱动层
4. **延迟检测**：可覆盖 `onDelayDetected(intervalMs)` 实现网络质量提示

### 示例（color_game）

```typescript
// frame_sync_protocal_layer.ts

export class FrameSyncProtocalLayer {
    public registerMsg(): void {
        MsgMgr.regMsgHandler(MsgType.GcGrabGiftFrame, this.revGcGrabGiftFrame, this);
        MsgMgr.regMsgHandler(MsgType.GcGrabGiftReconnect, this.revGcGrabGiftReconnect, this);
    }

    public sendGcGrabGiftFrame(roomId, frameIndex, x, y, direction, giftId, bagIndex, seqId): void {
        let msg = new sg.CgGrabGiftFrame();
        msg.roomId = new Int64(roomId);
        msg.frameIndex = frameIndex;
        msg.x = Math.round(x * 10000);
        msg.y = Math.round(y * 10000);
        msg.direction = Math.round(direction * 10000);
        msg.giftId = giftId;
        msg.bagIndex = bagIndex;
        msg.seqId = seqId;
        MsgMgr.sendMsg(msg, MsgType.CgGrabGiftFrame);
    }

    private revGcGrabGiftFrame(msgBuffer): void {
        let msg = NetUtils.UnpackageThriftMessageFromBytesArray(msgBuffer, sg.GcGrabGiftFrame);
        // 直接转交驱动层（驱动层内部做数据转换）
        FrameSyncDriverLayer.instance.addServerFrame(msg);
    }
}
```

## 第三步：实现驱动层

继承 `MngBaseFrameSyncDriver`，实现桥接逻辑。

### 必须实现

| 方法 | 说明 |
|------|------|
| `createConfig()` | 返回玩法配置（帧率、延迟帧数等） |
| `setupEventListeners()` | 将帧同步事件绑定到游戏事件系统 |
| `setupDataHandler()` | 设置数据处理器，将帧数据派发到逻辑层 |
| `getProtocol()` | 返回协议层实例 |
| `convertRawMsgToFrameData()` | 将协议原始消息转换为通用帧数据 |

### 数据处理器的三个回调

```typescript
{
    // 本地操作帧入缓冲区后回调（通常用于立即更新本地表现）
    onClientFrame(frameData) { ... },

    // 服务器帧到达后回调（核心！更新游戏状态）
    onServerFrame(frameData) { ... },

    // 重连/追帧回放批量帧到达后回调（可选，未实现则回退逐帧调用 onServerFrame）
    onServerFrameBatch(frames) { ... },
}
```

### 事件类型

| 事件 | 触发时机 |
|------|----------|
| `FRAME_UPDATE` | 逻辑帧或渲染帧推进时（data.type 区分 "logic" / "render"） |
| `FRAME_PREDICT` | 帧预测发生时 |
| `FRAME_CORRECT` | 帧矫正发生时 |
| `FRAME_LOST` | 检测到帧丢失时 |
| `FRAME_ERROR` | 帧同步错误时 |

### 示例（color_game）

```typescript
// frame_sync_driver_layer.ts

setupEventListeners(): void {
    this.clientSyncManager.on(FrameSyncEventType.FRAME_UPDATE, (data) => {
        if (data.type === "logic") {
            ColorGameEvent.emit(ColorGameEventType.LogicFrameUpdate, data.frame);
        } else if (data.type === "render") {
            ColorGameEvent.emit(ColorGameEventType.RenderFrameUpdate, {
                frame: data.frame,
                targetLogicFrame: data.targetLogicFrame,
            });
        }
    });
}

setupDataHandler(): void {
    this.clientSyncManager.setDataHandler({
        onClientFrame: (frameData) => {
            ColorGameEvent.emit(ColorGameEventType.SetLocalFrameData, { ... });
        },
        onServerFrame: (frameData) => {
            ColorGameEvent.emit(ColorGameEventType.SetServerFrameData, { frameData });
        },
        onServerFrameBatch: (frames) => {
            ColorGameEvent.emit(ColorGameEventType.SetServerFrameDataBatch, { frames });
        },
    });
}
```

## 第四步：在游戏主类中组装

### 初始化顺序

```
1. FrameSyncDriverLayer.init()       — 创建 SyncManager、绑定事件和数据处理器
2. FrameSyncProtocalLayer.init()     — 注册网络消息
3. FrameSyncDriverLayer.initSyncClient() — SyncManager 进入 RUNNING 状态
4. driver.setAddServerFrame(false)   — 允许接入服务器帧
```

### 主循环驱动

```typescript
// scene 的 update(dt) 中
update(dt: number): void {
    driver.updateLogicFrame(dt);
    driver.updateRenderFrame(dt);
}
```

### 发送本地操作

```typescript
// 摇杆移动时
driver.addClientFrame(logicFrame, frameInfo);
protocol.sendFrame(roomId, logicFrame, x, y, direction, ...);
```

### 销毁顺序

```
1. driver.setAddServerFrame(true)    — 禁止继续接入服务器帧
2. driver.unInit()                   — 销毁 SyncManager、清理事件
3. protocol.unInit()                 — 注销网络消息
```

## 第五步：处理断线重连

框架的驱动层内置缺帧检测机制：

1. 驱动层维护 `lastContiguousServerFrameIndex`（最后连续收到的帧号）
2. 收到帧号有缺口时，自动调用 `protocol.sendReconnect(roomId, missingStart)` 请求补帧
3. 协议层收到重连响应后，调用 `driver.reconnectGame(roomId, historyFrames)`
4. 驱动层内部使用 `beginServerFrameReplayBatch()` → 逐帧灌入 → `endServerFrameBatch(true)` 完成追帧

### 重连批处理模式

| 模式 | 方法 | 行为 |
|------|------|------|
| latest | `beginServerFrameBatch()` | 仅保留最新一帧，结束时 flush 一次 |
| replay | `beginServerFrameReplayBatch()` | 收集所有历史帧，结束时按序 flush（走 onServerFrameBatch） |
